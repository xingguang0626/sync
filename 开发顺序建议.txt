
# Life MVP 开发优先级表

## P0：必须完成，不做就不能演示

| 模块   | 功能      | 具体任务                                         | 负责人建议         | 验收标准              |
| ---- | ------- | -------------------------------------------- | ------------- | ----------------- |
| 项目基础 | 项目搭建    | 创建前端项目、统一目录结构、配置路由/导航                        | 前端 B/C        | App 能正常运行，页面可切换   |
| 数据层  | 日程数据结构  | 定义 schedule 数据模型：标题、日期、开始时间、结束时间、持续时间、优先级、状态 | 后端/数据 D       | 能创建一条完整日程数据       |
| 数据层  | 本地存储    | 使用本地数据库或本地缓存保存日程                             | 后端/数据 D       | 关闭重开 App 后日程仍存在   |
| 首页   | 首页主界面   | 实现顶部区域、今日日期、AI 卡片区域、时间轴区域、底部输入栏              | 前端 B          | 首页 UI 基本完整        |
| 首页   | 日程卡片    | 显示名称、时间、持续时间、优先级、状态                          | 前端 B          | 每张卡片信息完整          |
| 首页   | 优先级颜色   | P0/P1/P2 使用同一色系不同深浅                          | 前端 B + 产品 A   | P0 最深，P1 中等，P2 最浅 |
| 时间轴  | 基础排序    | 按开始时间从早到晚排序                                  | 后端 D + 前端 B   | 新增日程后能自动插入正确位置    |
| 新建日程 | 手动新建    | 点击“+”进入新建页，填写标题、日期、时间、持续时间、优先级               | 前端 C          | 能完整填写并保存          |
| 新建日程 | 字段校验    | 标题、时间、持续时间不能为空或非法                            | 前端 C + 后端 D   | 缺字段时不能保存          |
| 新建日程 | 保存后刷新首页 | 保存成功后重新生成当天时间轴                               | 前端 B/C + 后端 D | 首页立即出现新日程         |

## P1：核心智能感，P0 完成后立刻做

| 模块    | 功能       | 具体任务                             | 负责人建议       | 验收标准                             |
| ----- | -------- | -------------------------------- | ----------- | -------------------------------- |
| 时间轴   | 冲突检测     | 判断两个日程时间段是否重合                    | 后端/数据 D     | 能识别 15:00-16:30 与 15:30-16:00 冲突 |
| 时间轴   | 冲突显示     | 2 个重合事件并列显示，3 个以上显示冲突组           | 前端 B        | 首页不会混乱堆叠                         |
| 时间轴   | 冲突二级菜单   | 点击冲突组后打开底部菜单，展示完整冲突列表            | 前端 C        | 能查看冲突详情                          |
| 自然语言  | 本地规则解析   | 支持“明天早上8点跑步”“晚上10点deadline”等基础句式 | 后端/数据 D     | 测试句能生成正确草稿                       |
| 自然语言  | 确认卡片     | 自然语言解析后不直接保存，先展示确认添加             | 前端 C        | 用户确认后才创建                         |
| AI 提醒 | 时间冲突提醒   | 新日程与已有日程冲突时生成提醒                  | 后端 D + 前端 B | 首页显示冲突提醒卡                        |
| AI 提醒 | 晚间 P0 提醒 | 20:00 后新增 P0 任务时触发提醒             | 后端 D + 前端 B | “今晚10点deadline”能触发提醒             |
| AI 提醒 | 二级建议菜单   | 点击 AI 卡片后展示“查看调整 / 稍后处理 / 采纳建议”  | 前端 C        | 用户能进入建议详情                        |

## P2：让产品更完整，有时间就做

| 模块    | 功能       | 具体任务                  | 负责人建议       | 验收标准        |
| ----- | -------- | --------------------- | ----------- | ----------- |
| 日程管理  | 编辑日程     | 点击日程进入详情，可修改标题、时间、优先级 | 前端 C + 后端 D | 修改后首页同步更新   |
| 日程管理  | 删除日程     | 删除前二次确认               | 前端 C + 后端 D | 删除后首页不再显示   |
| 日程管理  | 标记完成     | 日程可切换为已完成状态           | 前端 B/C      | 已完成任务视觉弱化   |
| AI 提醒 | 连续学习过久提醒 | 连续学习超过 90 分钟提醒休息      | 后端 D        | 能生成“建议休息”提醒 |
| AI 提醒 | 未完成顺延    | 晚上仍有未完成任务时提示顺延到明天     | 后端 D + 前端 C | 点击后能生成明天任务  |
| 预设模式  | 学习/放松/小憩 | 三个基础模式入口和倒计时          | 前端 C        | 能进入模式并结束    |
| 预设模式  | 结束反馈     | 结束后显示正向反馈文案           | 前端 C + 产品 A | 不出现批评式文案    |
| 生活管家  | 占位页      | 做入口页、今日状态卡、生活建议占位     | 前端 C        | 页面可进入，风格统一  |
| 我的/设置 | 基础设置页    | 关于 Life、通知开关占位、数据清理入口 | 前端 C        | 页面完整但功能可简化  |

## P3：后续版本，不进 MVP

| 模块    | 功能         | 暂缓原因           |
| ----- | ---------- | -------------- |
| 语音输入  | 真正语音识别     | 成本高，MVP 先保留按钮  |
| 外部 AI | 复杂 AI 自动排程 | 先用本地规则，避免不稳定   |
| 定位识别  | 深夜仍在公司提醒   | 涉及权限和隐私，后续再做   |
| 健康数据  | 睡眠/身体数据分析  | 生活管家功能还未完全清晰   |
| 多端同步  | 账号登录和云同步   | MVP 先本地存储      |
| 统计分析  | 完成率、趋势图    | 可作为展示增强，不是核心闭环 |
| 通知系统  | 系统级推送提醒    | 需要平台权限，后续做     |
| 日历导入  | 接入系统日历     | 开发成本较高，暂缓      |

---

# 推荐开发顺序

## 第 1 阶段：先让 App 跑起来

优先做：

1. 项目搭建
2. 首页静态 UI
3. 日程数据结构
4. 本地存储
5. 手动新建日程
6. 首页时间轴展示

这一阶段完成后，App 至少能演示：

> 点击 “+” 新建日程 → 首页按时间显示。

---

## 第 2 阶段：做时间轴核心体验

优先做：

1. 时间排序
2. P0/P1/P2 颜色深浅
3. 冲突检测
4. 两个事件并列显示
5. 三个以上事件显示冲突组
6. 点击冲突组打开二级菜单

这一阶段完成后，产品的“智能日程主控台”感觉会出来。

---

## 第 3 阶段：做自然语言和 AI 提醒

优先做：

1. 本地自然语言规则解析
2. 自然语言生成日程草稿
3. 确认添加卡片
4. 晚间 P0 提醒
5. 时间冲突提醒
6. AI 提醒二级菜单

这一阶段完成后，能演示核心亮点：

> 输入“今晚 10 点 deadline” → 生成 P0 任务 → 触发 AI 提醒。

---

## 第 4 阶段：补完整度

有时间再做：

1. 编辑/删除日程
2. 标记完成
3. 学习/放松/小憩模式
4. 生活管家占位页
5. 设置页
6. 演示流程优化

---

# 最终优先级一句话

你们开发时可以按这个顺序执行：

> **先做日程能创建和显示，再做时间轴排序与冲突，再做自然语言输入，最后做 AI 提醒和预设模式。**

最小可演示版本只要完成：

| 必须演示能力          | 是否核心 |
| --------------- | ---- |
| 首页能显示今日时间轴      | 核心   |
| 能手动新建日程         | 核心   |
| 日程能按时间排序        | 核心   |
| P0/P1/P2 颜色深浅区分 | 核心   |
| 自然语言能生成日程草稿     | 核心   |
| 晚间 P0 能触发 AI 提醒 | 核心   |
| 冲突事件能显示二级菜单     | 核心   |

这几项做完，MVP 就已经成立了。
