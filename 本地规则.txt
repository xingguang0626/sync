
# Life 本地自然语言解析规则 v1.0

## 一、规则目标

本地规则负责把用户输入的一句话转成以下结果：

```json id="zy68ah"
{
  "intent": "create_schedule",
  "title": "deadline",
  "date": "today",
  "startTime": "22:00",
  "duration": 60,
  "priority": "P0",
  "repeat": "none",
  "confidence": 0.9,
  "needConfirmation": true
}
```

本地规则不追求完全理解所有语言，只处理高频、明确、可控的表达。

一句话原则：

> 简单明确的输入由本地规则处理；模糊复杂的输入交给外部 AI；任何影响时间轴的操作都需要用户确认。

---

# 二、整体解析流程

用户输入一句话后，系统按这个顺序处理：

```text id="manpoq"
1. 清洗文本
2. 判断用户意图
3. 识别日期
4. 识别时间
5. 识别持续时间
6. 识别重复频率
7. 识别优先级
8. 识别任务名称
9. 补默认值
10. 校验结果
11. 生成日程草稿或操作建议
12. 用户确认后执行
```

注意：
**本地规则只生成草稿，不直接保存。**

---

# 三、文本清洗规则

在解析前，先统一处理用户输入。

## 1. 去除多余符号

用户输入：

```text id="jr5zcy"
明天！！！下午3点，，，学习90分钟
```

系统先转成：

```text id="j15yh8"
明天下午3点学习90分钟
```

## 2. 统一大小写

```text id="fdpifv"
Deadline
deadline
DEADLINE
```

都识别为：

```text id="2xwirf"
deadline
```

## 3. 统一数字

中文数字要转成阿拉伯数字。

| 用户输入  | 转换后   |
| ----- | ----- |
| 一点    | 1点    |
| 两小时   | 2小时   |
| 半小时   | 30分钟  |
| 一个半小时 | 1.5小时 |
| 一小时半  | 1.5小时 |
| 三十分钟  | 30分钟  |

---

# 四、意图识别规则

先判断用户想做什么。

## 1. 创建日程

只要句子里出现任务内容 + 时间表达，默认是创建日程。

例如：

```text id="iaiqjj"
明天早上8点跑步
今天下午3点学习90分钟
晚上10点deadline
周五下午4点小组会议
```

识别为：

```text id="dlncx1"
intent = create_schedule
```

---

## 2. 修改日程

出现以下关键词时，识别为修改：

```text id="0lvbcl"
改到
调整到
挪到
换到
提前到
推迟到
延后到
改成
```

例如：

```text id="y3nk3m"
把学习改到晚上8点
把跑步推迟到明天早上
小组会议提前到下午2点
```

识别为：

```text id="lmwnna"
intent = update_schedule
```

---

## 3. 删除日程

出现以下关键词时，识别为删除：

```text id="to79n2"
取消
删除
删掉
不要了
不去了
不用了
```

例如：

```text id="xc4f8d"
取消今晚跑步
删掉明天的会议
晚上读书不要了
```

识别为：

```text id="42z5rz"
intent = delete_schedule
```

删除必须二次确认。

---

## 4. 顺延日程

出现以下关键词时，识别为顺延：

```text id="w7w8u9"
顺延
明天再做
以后再做
晚点做
推后
挪到明天
```

例如：

```text id="52a4su"
把今天没做完的顺延到明天
这个任务明天再做
晚读晚点做
```

识别为：

```text id="n2cau2"
intent = move_schedule
```

---

## 5. 开启模式

出现以下关键词时，识别为模式操作：

```text id="l3iopx"
学习模式
专注模式
放松模式
小憩模式
休息一下
进入心流
加班模式
```

例如：

```text id="4jou1q"
开启学习模式
我想休息一下
进入加班模式
```

识别为：

```text id="cntvll"
intent = start_mode
```

---

## 6. 无法判断

如果没有明确任务、时间、动作，例如：

```text id="9awdst"
有点烦
今天好多事
那个东西晚点弄
```

识别为：

```text id="87rgmb"
intent = unknown
```

系统不创建日程，提示用户补充。

# 五、日期识别规则

## 1. 明确日期

| 用户表达      | 识别结果                     |
| --------- | ------------------------ |
| 今天        | today                    |
| 明天        | tomorrow                 |
| 后天        | today + 2                |
| 大后天       | today + 3                |
| 昨天        | yesterday，仅用于查询或修改，不用于新建 |
| 今晚        | today                    |
| 明早        | tomorrow                 |
| 明晚        | tomorrow                 |
| 本周五 / 这周五 | 当前周的周五                   |
| 下周一       | 下一周的周一                   |

---

## 2. 星期表达

| 用户表达           | 识别结果      |
| -------------- | --------- |
| 周一 / 星期一 / 礼拜一 | Monday    |
| 周二 / 星期二 / 礼拜二 | Tuesday   |
| 周三 / 星期三 / 礼拜三 | Wednesday |
| 周四 / 星期四 / 礼拜四 | Thursday  |
| 周五 / 星期五 / 礼拜五 | Friday    |
| 周六 / 星期六 / 礼拜六 | Saturday  |
| 周日 / 星期日 / 礼拜天 | Sunday    |

规则：

如果用户说“周五”，但没有说“本周”还是“下周”：

* 如果本周周五还没到，默认本周周五。
* 如果本周周五已经过去，默认下周周五。

---

## 3. 没有日期时

如果用户只说：

```text id="iwkvgg"
下午3点学习
```

默认日期为：

```text id="i8g3g2"
今天
```

但是如果当前时间已经晚于输入时间，例如现在是 18:00，用户说：

```text id="1garhs"
下午3点学习
```

MVP 建议：

```text id="bh6gq8"
默认安排到明天 15:00，并在确认卡片里提示用户。
```

确认文案：

```text id="j3of3b"
现在已经过了今天15:00，我先帮你安排到明天15:00，可以修改。
```

# 六、时间识别规则

## 1. 明确时间

| 用户表达  | 识别结果                |
| ----- | ------------------- |
| 上午8点  | 08:00               |
| 早上8点  | 08:00               |
| 中午12点 | 12:00               |
| 下午3点  | 15:00               |
| 晚上8点  | 20:00               |
| 晚上10点 | 22:00               |
| 23:30 | 23:30               |
| 7点半   | 07:30 或 19:30，根据上下文 |
| 8点15  | 08:15 或 20:15，根据上下文 |

---

## 2. 没有上午下午时

如果用户只说：

```text id="3n0sp5"
8点跑步
```

系统根据任务类型判断：

| 任务类型          | 默认时间判断          |
| ------------- | --------------- |
| 跑步 / 早餐 / 上课  | 早上 8:00         |
| 晚读 / 睡前 / 晚饭  | 晚上 8:00         |
| deadline / 提交 | 晚上 8:00 或 22:00 |
| 会议 / 学习 / 复习  | 默认当天 8:00，需要确认  |

如果无法判断，展示确认卡片：

```text id="bju1bx"
你是想安排在早上8点，还是晚上8点？
```

---

## 3. 模糊时间默认值

| 用户表达 | 默认时间  |
| ---- | ----- |
| 早上   | 08:00 |
| 上午   | 09:00 |
| 中午   | 12:00 |
| 下午   | 15:00 |
| 傍晚   | 18:00 |
| 晚上   | 20:00 |
| 今晚   | 21:00 |
| 睡前   | 22:30 |
| 放学后  | 17:00 |
| 下课后  | 17:00 |
| 起床后  | 08:00 |

例如：

```text id="9bqn2p"
今晚读书
```

解析为：

```text id="5y9vlp"
今天 21:00 读书
```

---

## 4. 时间段表达

| 用户表达      | 识别方式                               |
| --------- | ---------------------------------- |
| 3点到5点学习   | startTime = 15:00，endTime = 17:00  |
| 下午2点到4点开会 | startTime = 14:00，endTime = 16:00  |
| 晚上8点到9点跑步 | startTime = 20:00，endTime = 21:00  |
| 10点前完成作业  | endTime = 10:00，startTime 根据默认时长反推 |
| 8点后读书     | startTime = 20:00，duration 使用默认值   |

如果有明确开始和结束时间，优先使用时间段计算持续时间。

```text id="ks83lt"
deadline
ddl
截止
截至
今天必须
必须完成
很急
紧急
最重要
考试
面试
提交
交作业
汇报
演讲
比赛
```

例如：

```text id="iz67bi"
今晚10点deadline
明天考试
下午提交作业
```

识别为：

```text id="qtvycz"
priority = P0
```

---

## 2. P1 中优先级

出现以下词，识别为 P1：

```text id="grvt1a"
重要
学习
复习
开会
小组讨论
作业
项目
练习

```

默认大多数普通任务也是 P1。

---

## 3. P2 低优先级

```text id="h0wfyj"

午睡

看剧
整理
有空再做
不急

```

---

## 4. 明确优先级覆盖默认规则

如果用户明确说：

```text id="v8sycm"

```

则以用户明确表达为准。

例如：

```text id="i704ov"

```

虽然跑步默认可能是 P2，但用户明确写 P0，所以识别为 P0。

# 十、任务名称识别规则

任务名称是去掉日期、时间、时长、重复频率、优先级词之后，剩下的核心动作或名词。

例如：

```text id="xdkl1r"
明天下午3点学习90分钟
```

去掉：

```text id="4vtpk1"
明天 / 下午3点 / 90分钟
```

剩下：

```text id="qoy59k"
学习
```

所以：

```text id="p8hi2k"
title = 学习
```

---

# 十二、置信度规则

本地规则需要给每次解析打一个置信度。

## 高置信度：0.85 - 1.0

满足：

```text id="ty0kyc"
有明确任务名称
有明确日期或可默认日期
有明确时间
```

例如：

```text id="nkhqn6"
明天下午3点学习90分钟
```

处理方式：

```text id="o9k58a"
直接展示确认卡片
```

---

## 中置信度：0.6 - 0.85

满足：

```text id="arixuu"
有任务名称
但时间或日期有点模糊
```

例如：

```text id="vigiko"
晚上学习
```

处理方式：

```text id="8xx03m"
使用默认时间，但在确认卡片里提示可修改
```

---

## 低置信度：低于 0.6

缺少关键字段，或者指代不清。

例如：

```text id="cqzh2g"
那个明天再说
晚点弄一下
有点忙
```

处理方式：

```text id="7psjqp"
不生成日程，提示用户补充
```

---

# 十三、字段缺失处理规则

| 缺失字段  | 处理方式              |
| ----- | ----------------- |
| 缺标题   | 不创建，提示补充任务内容      |
| 缺日期   | 默认今天              |
| 缺时间   | 进入补全流程，或使用模糊时间默认值 |
| 缺持续时间 | 使用任务类型默认时长        |
| 缺优先级  | 默认 P1             |
| 缺重复频率 | 默认 none           |

提示文案：

```text id="j45biu"
我理解了一部分，可以再补充一下时间吗？
```

---

# 十四、操作安全规则

以下操作必须二次确认：

| 操作     | 原因       |
| ------ | -------- |
| 删除日程   | 不可直接执行   |
| 修改已有日程 | 可能影响用户安排 |
| 顺延多个日程 | 影响时间轴    |
| 开启加班模式 | 影响提醒策略   |
| 修改睡眠安排 | 涉及生活节奏   |
| 清空当天安排 | 高风险操作    |

本地规则绝不直接执行这些操作，只生成确认卡片。


# 十六、与时间轴联动规则

本地规则生成日程草稿后，还要进入时间轴逻辑。

流程：

```text id="pnzqff"
生成日程草稿
↓
用户确认
↓
保存日程
↓
重新生成当天时间轴
↓
检查是否有重合
↓
如果有重合，生成冲突提醒
↓
如果晚间 P0，生成加班模式提醒
```

例如用户输入：

```text id="fzvevt"
今晚10点deadline
```

系统保存前展示：

```text id="6rz887"
日程：Deadline
时间：今天 22:00 - 23:00
优先级：P0
```

用户确认后：

```text id="mp7v34"
保存日程
刷新时间轴
检测晚间 P0
生成 AI 提醒卡片
```
