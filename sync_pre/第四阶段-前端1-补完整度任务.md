## 二、API 路径约定（RESTful 风格）

| HTTP 方法 | 路径 | 处理函数 | 调用的 db.py 函数 |
| --- | --- | --- | --- |
| `GET`    | `/api/timeline?date=` | `handle_timeline` | `timeline.get_timeline` |
| `POST`   | `/api/schedules` | `handle_create_schedule` | `db.create_schedule` |
| `GET`    | `/api/schedules/{id}` | `handle_get_schedule` | `db.get_schedule` |
| `PUT`    | `/api/schedules/{id}` | `handle_update_schedule` | `db.update_schedule` |
| `DELETE` | `/api/schedules/{id}` | `handle_delete_schedule` | `db.delete_schedule` |
| `POST`   | `/api/schedules/{id}/complete` | `handle_mark_complete` | `db.mark_complete` |
| `POST`   | `/api/schedules/{id}/postpone` | `handle_postpone_schedule` | `db.postpone_schedule` |
| `GET`    | `/api/reminders/check?date=` | `handle_reminders` | `reminders.check_reminders` |
| `POST`   | `/api/nlu/parse` | `handle_nlu_parse` | `nlu.parse` |

> **设计原则**：用标准 HTTP 方法语义（GET=读 / PUT=改 / DELETE=删），避免之前 `GET /api/schedules/{id}/delete` 这种"用 GET 触发删除"的安全隐患。

## 四、关键代码契约（API 字段不变）

### 4.1 请求体（PUT /api/schedules/{id}）

```json
{
  "title": "深度学习",
  "date": "2026-07-04",
  "start_time": "15:00",
  "duration": 90,
  "priority": "P0",
  "repeat": "none",
  "note": "Kotlin + Compose 实战"
}
```

> 与 POST /api/schedules 完全相同的字段集。`status` 字段后端不支持外部修改（只在 mark_complete 时系统改）。

### 4.2 响应体（所有接口统一）

```json
// 成功
{"ok": true, "data": {...}}

// 失败
{"ok": false, "error": "具体原因"}
```

> 错误状态码：
> - 200：成功
> - 201：创建成功
> - 400：参数错误（缺字段、字段非法）
> - 404：日程不存在

### 4.3 postpone 请求体（可选）

```json
// POST /api/schedules/{id}/postpone
// 请求体可空（默认顺延到明天）或：
{"new_date": "2026-07-05"}
```
