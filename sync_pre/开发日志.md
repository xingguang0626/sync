## 前端交互闭环补全（2026-07-04 深夜 · mengyiguang）

### 背景

此前 ConflictBottomSheet、ReminderBottomSheet、NluConfirmCard 三个组件已单独写好，但都未接入 HomeScreen 实际交互流。此次一次性补齐所有前端交互闭环。

### 改动详情

**1. HomeUiState + HomeUiEvent — 重写**
- 新增 BottomSheet 状态字段：`showConflictSheet`、`conflictSchedules`、`showReminderSheet`
- 新增 NLU 确认状态字段：`showNluConfirm`、`nluDraft`、`nluInputText`
- 事件新增：`ShowConflictSheet(List<Schedule>)` / `DismissConflictSheet` / `ShowReminderSheet` / `DismissReminderSheet` / `DismissNluConfirm` / `ConfirmNluDraft`
- 移除旧事件：`ConflictGroupClicked(List<Long>)`、`ReminderClicked`、`AdoptReminderSuggestion`、`ViewReminderAdjustment`

**2. HomeViewModel — Mock NLU 解析**
- `SendInput` 事件 → `mockNluParse(text)` 生成 `NluDraftPreview`
- 简单关键词匹配：学习/会议/deadline/运动 → 提取标题
- 正则提取时间：`(\d{1,2})[:：点](\d{0,2})?`
- 优先级推断：P0/deadline/重要 → P0、P1 → P1、其它 → P2
- 置信度分层：≥6字符+时间匹配 → 0.88、≥4字符 → 0.72、其它 → 0.40
- 所有 BottomSheet 显示/关闭事件直接更新 UiState

**3. HomeScreen — 三个内嵌弹窗**
- **ConflictBottomSheet**：`showConflictSheet=true` 时渲染，传入完整 `List<Schedule>`，建议文案根据冲突数量动态生成
- **ReminderBottomSheet**：`showReminderSheet=true` 时渲染，从当前加载的 `HomePageData.topReminder` 获取 Reminder 数据
- **NluConfirmCard**：`showNluConfirm=true` 时在输入栏上方显示，确认→刷新首页，修改→关闭卡片并跳转手动新建
- `ReminderCard` 两个按钮统一触发 `ShowReminderSheet` 事件
- `TimelineSection` 冲突点击：改为传 `List<Schedule>`（不再传 `List<Long>`）

**4. TimelineSection / ConflictPairCard / ConflictGroupCard — 回调改造**
- `onConflictGroupClick` 签名从 `(List<Long>)` 改为 `(List<Schedule>)`
- ConflictGroupCard 去除展开/折叠行为（点击直接弹出 BottomSheet），改为显示日程标题摘要 + "点击查看冲突详情"

**5. MainActivity — 清理**
- 移除 `onNavigateToConflictMenu` 回调参数
- 删除 `conflict_menu` 路由

**6. 删除废弃文件**
- `ConflictMenuPlaceholder.kt` — 已被 ConflictBottomSheet 替代
- `ScheduleDetailPlaceholder.kt` — 已被 ScheduleDetailScreen 替代

## 实机调试修复（2026-07-04 晚间）

### 修复的问题

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 保存成功后首页不刷新 | `popBackStack()` 不销毁 HomeViewModel，`loadHome()` 不重新执行 | `navigate("home") { popUpTo("home") { inclusive = true } }` |
| 2 | 保存失败无任何提示 | `errors["_save"]` 设置了但 UI 无展示 | 添加 `LaunchedEffect` + `Snackbar` 弹出错误 |

#### 2.4 `server.py` — HTTP 服务入口

**职责：** 提供 RESTful HTTP API，作为前端（Kotlin/Android）与后端（Python）之间的通信桥梁。

##### 2.4.1 启动方式

```bash

```

##### 2.4.2 监听配置

| 配置项 | 值 | 说明 |

| `PORT` | `8800` | 与前端 `build.gradle.kts` 中的 `BASE_URL` 一致 |

##### 2.4.3 路由表（`ROUTES` 字典，定义于文件顶部）

| 方法 | 路径 | 处理函数 | 前端调用方 | 阶段 |
|------|------|---------|-----------|------|
| `GET` | `/api/timeline` | `handle_timeline` → `timeline.get_timeline(date)` | `KtorHomeApi.getTimeline()` | P0 |
| `POST` | `/api/schedules` | `handle_create_schedule` → `db.create_schedule(body)` | `NewScheduleViewModel`（待 mengyiguang 接入） | P0 |
| `GET` | `/api/reminders/check` | `handle_reminders` → `reminders.check_reminders(date)` | `KtorHomeApi.checkReminders()` | P0 |
| `OPTIONS` | `*` | 返回 CORS 头 | 浏览器预检（非必须，预留） | — |

##### 2.4.4 路由处理函数

| 函数 | 输入 | 输出 | HTTP 状态码 |
|------|------|------|-----------|
| `handle_timeline(params)` | URL query 参数 `{"date":["2026-07-03"]}` | `(200, result)` 或 `(400, error)` | 200 / 400 |
| `handle_create_schedule(body)` | JSON 解析后的 dict | `(201, result)` 或 `(400, error)` | 201 / 400 |
| `handle_reminders(params)` | URL query 参数 | `(200, result)` 或 `(400, error)` | 200 / 400 |

##### 2.4.5 启动流程

1. 打印 banner
2. 调用 `db.init_db()` 初始化数据库
3. 如果初始化失败 → 打印错误并退出（`sys.exit(1)`）
4. 启动 `HTTPServer` 并进入 `serve_forever()` 循环
5. 按 `Ctrl+C` 优雅退出

##### 2.4.6 关键设计决策

- **使用 Python 标准库 `http.server`**，不依赖第三方包（FastAPI/Flask），降低学习成本和部署复杂度
- **`_json_bytes()`** 使用 `ensure_ascii=False` 保证中文在 HTTP 响应中直接以 UTF-8 编码传输
- **CORS 支持**：`Access-Control-Allow-Origin: *`，方便将来可能的 Web 调试
- **OPTIONS 预检**：支持浏览器跨域请求，但非 Android 必需（Ktor 客户端不发送预检）
- **异常捕获**：所有 handler 包裹在 try/except 中，避免 500 错误导致服务崩溃

**开发目标：** 将系统 `SpeechRecognizer`（依赖 Google/讯飞服务）替换为 Vosk 离线语音识别引擎，实现完全离线、无需联网的中文语音输入。

| `voice/VoskVoiceHelper.kt` | 离线语音识别封装：AudioRecord PCM 采集（16kHz mono 16bit）→ `acceptWaveForm` 识别 → partial/final 回调 |

### 架构

```
HomeScreen                   HomeViewModel                  VoskModelManager       VoskVoiceHelper
  │                             │                               │                      │
  │ InitVoskModel ────────────►│                               │                      │
  │                             │ isModelDownloaded()? ───────►│                      │
  │                             │◄── true/false ───────────────│                      │
  │                             │ ensureModel() ──────────────►│ download + extract   │
  │                             │◄── downloadState flow ──────│                      │
  │ voskModelProgress ────►    │                               │                      │
  │                             │ initialize(modelPath) ────────────────────────►   │
  │                             │                               │                      │
  │ OnVoiceClick ─────────────►│                               │                      │
  │                             │ startListening() ───────────────────────────►     │
  │                             │                               │   AudioRecord PCM   │
  │                             │◄── onPartialResult ──────────────────────────     │
  │◄─ voicePartialText ────── │                               │                      │
  │                             │◄── onFinalResult ───────────────────────────     │
  │◄─ nluInputText=text ────  │                               │                      │
  │  → SendInput → NLU         │                               │                      │
```

### 关键技术点

- **JNA 冲突处理**：vok-android 传递依赖 `jna`（JAR），Android 需要 `jna@aar`（含 Android 原生库）。通过 `exclude(group="net.java.dev.jna")` 排除传递依赖，单独添加 `@aar` 变体。
- **AudioRecord 阻塞读取**：`recorder.read()` 在 stop 后仍阻塞，解决方案是在 `stopListening()` 中先 `recorder.stop()` 再 `job.cancel()`，通过 `currentRecorder` 字段直接访问录音实例。
- **finalResult 获取**：录音结束时若 `acceptWaveForm` 未返回 true，调用 `recognizer.finalResult` 获取最终结果，避免静音尾巴丢失。
- **并发下载防护**：`synchronized(downloadLock)` + `isDownloading` 标志双重检查，防止快速双击触发重复下载。
- **Zip Slip 防护**：`extractZip()` 验证每个 entry 的 canonical path 是否在解压目标目录内。

### 交互流程

1. 进入首页 → `LaunchedEffect` 触发 `InitVoskModel` → 检查模型是否已下载
2. 模型已下载 → 直接初始化 Recognizer → `voskModelReady = true`
3. 模型未下载 → 等待用户点击麦克风 → 触发 `ensureModel()` → 下载进度条显示
4. 下载完成 → 自动初始化为 Recognizer → 开始录音识别
5. 录音中：partial 结果实时回显 → final 结果自动填入输入框 → NLU 解析
